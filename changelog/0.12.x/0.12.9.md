# 0.12.9 — 2026-09-12

## Changed

- **Bun engines floor raised to `>=1.4.0`** — required by the mirror driver's `close(true)` fix below.
- **`MirrorStore` migrations run on a fresh database too** ([#303](https://github.com/cyanheads/mcp-ts-core/issues/303)) — `up()` runs on first creation as well as upgrade, so a migration owning auxiliary objects (junction tables, denormalized counters) creates them there too. An existing `up()` that assumes an older table shape — a bare `ALTER TABLE … ADD COLUMN` — now fails on first creation.
- Shipped skills: `add-tool` 2.23, `api-errors` 1.10, `api-mirror` 1.2, `design-mcp-server` 2.25, `field-test` 2.14, `git-wrapup` 1.16, `polish-docs-meta` 2.13, `release-and-publish` 2.16, `security-pass` 1.8.

## Fixed

- **`IdGenerator.generateRandomString` rejects a charset outside 1–256 characters** ([#414](https://github.com/cyanheads/mcp-ts-core/issues/414)) — an empty or longer charset spun the rejection sampler forever; it now throws a validation error before reaching it.
- **The Bun mirror driver closes with `close(true)`** ([#364](https://github.com/cyanheads/mcp-ts-core/issues/364)) — bare `close()` left `prepare()`d statements live, holding the file open until garbage collection; `better-sqlite3` is unchanged.
- **`devcheck`'s Security Audit parses Bun 1.4's `bun audit` output** ([#390](https://github.com/cyanheads/mcp-ts-core/issues/390)) — the `name@version` header, `>` path separator, and literal `(direct dependency)` path are now recognized alongside the pre-1.4 shapes.
- **`devcheck`'s Outdated step attributes an unmarked row to the `dependencies` block** ([#422](https://github.com/cyanheads/mcp-ts-core/issues/422)) — a prod dependency also declared as a peer no longer reports "attribution is ambiguous."
- **The landing page's curl snippet sends a handshake `initialize` accepts** ([#395](https://github.com/cyanheads/mcp-ts-core/issues/395)) — it pinned the modern protocol revision behind an `MCP-Protocol-Version` header; it now sends `LATEST_PROTOCOL_VERSION` with `Accept: application/json, text/event-stream`.
- **A cancelled single-request POST's SSE stream closes immediately** ([#401](https://github.com/cyanheads/mcp-ts-core/issues/401)) — `notifications/cancelled` for an in-flight request now closes that request's stream via the SDK transport's `closeSSEStream`, instead of holding it open to keep-alive or session expiry. A batched POST's ids share one stream and are left for the SDK to free.
