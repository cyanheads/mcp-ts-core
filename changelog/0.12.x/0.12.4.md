# 0.12.4 — 2026-09-02

## Added

- **`JsonRpcErrorCode.RequestCancelled` (-32011) and the `requestCancelled()` factory** on `/errors` ([#386](https://github.com/cyanheads/mcp-ts-core/issues/386)) — the code for a caller that went away. It is an `error-contract-conformance` baseline code, so no tool declares it; `withRetry` treats it as non-transient and the HTTP transport answers `499`.

## Changed

- **No HTTP status maps to `InternalError`** ([#323](https://github.com/cyanheads/mcp-ts-core/issues/323)) — that code means *this* server failed, which a remote status cannot establish. 500 and 501 join the rest of the 5xx range as `ServiceUnavailable`; 504 stays `Timeout` and 4xx is unchanged.
- **A 501 carries `data.retryable: false`** — it now shares `ServiceUnavailable`'s transient code, so the in-band opt-out is what keeps a method the upstream does not implement out of `withRetry`. Both `httpErrorFromResponse` and `fetchWithTimeout` set it.
- Shipped skills: `add-tool` 2.21, `api-config` 1.14, `api-context` 2.2, `api-errors` 1.8, `api-linter` 1.13, `api-utils` 2.7, `design-mcp-server` 2.23, `maintenance` 2.6, `release-and-publish` 2.13.

## Fixed

- **A client disconnect mid-call classifies as a cancellation** — `fetchWithTimeout`'s external-abort path no longer hand-builds `InternalError`, and `determineErrorCode` matches the SDK's `ConnectionClosed` rejection by code ahead of the pattern ladder, so the wording that says "aborted" is not read as a `Timeout`. Logged at `info` with no stack.
- **An upstream 500 retries** — its `InternalError` classification sat outside `withRetry`'s default transient set, so it failed on the first attempt while the 502 beside it retried.
- **Multi-arch Docker publish no longer fails on an arm64 host** ([#370](https://github.com/cyanheads/mcp-ts-core/issues/370)) — the build stage in `Dockerfile` and `templates/Dockerfile` is pinned to `$BUILDPLATFORM`, so the `linux/amd64` leg cross-compiles instead of running under QEMU, where bun >= 1.4 aborts inside `bun run build` and no image publishes for either architecture. A build stage that compiles a native addon cannot cross-compile this way; `templates/Dockerfile` states the constraint.
- **Downstream skill sync reaches `release-and-publish` again** ([#372](https://github.com/cyanheads/mcp-ts-core/issues/372)) — its stamp had regressed 2.12 → 1.11, so the `maintenance` skill read every consumer copy as a local override and skipped it permanently. 2.13 clears the fleet high-water mark, and Phase A now reports each skipped skill with both versions.

## Security

- **The SSRF DNS guard queries both resolvers** ([#365](https://github.com/cyanheads/mcp-ts-core/issues/365)) — `assertDnsNotPrivate` adds `dns.lookup(hostname, { all: true })` beside `resolve4`/`resolve6` and rejects a non-global answer from either. Bun 1.4 left `dns.resolve*()` on c-ares while moving Linux hostname resolution in `net.connect()` to `getaddrinfo`, so a name only the system resolver could see — `/etc/hosts`, split DNS, an NSS module — passed the guard and then connected. Each probe settles independently, so a resolver absent from the runtime is skipped rather than fatal.
