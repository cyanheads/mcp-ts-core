# 0.10.14 — 2026-07-06

## Fixed

- **Docker build stage** — installs with `bun install --frozen-lockfile --ignore-scripts`, matching the production stage, so a dependency's native postinstall (`better-sqlite3`'s `prebuild-install` → `node-gyp`, unsupported under Bun) no longer aborts `docker build` with exit 127. The build only runs `tsc`, which needs type declarations, not compiled bindings; `templates/Dockerfile` mirrors the fix. [#267](https://github.com/cyanheads/mcp-ts-core/issues/267)
- **`definition-invalid` lint rule** — `validateDefinitions()` surfaces a `null`/`undefined`/non-object entry in a `tools`, `resources`, or `prompts` array as a `definition-invalid` error and skips it, instead of throwing a `TypeError` that aborts the whole lint run (previously only the `prompts` path survived). The three shared sub-linters (`lintEnrichmentContract`, `lintCappedListTruncation`, `lintHandlerBody`) early-return on a non-object `def`, and each per-definition loop guards before dispatch. [#265](https://github.com/cyanheads/mcp-ts-core/issues/265)
- **Canvas `importFrom` error contract** — the missing-source-table `notFound` carries `reason: 'missing_table'` and a `recovery.hint` (re-check the name or `describe()` the source canvas), matching `query()`'s precedent, so a consumer's declared error contract populates on the wire; the sibling `import_same_canvas` and `import_view_clash` throws gain `recovery.hint`s too. [#264](https://github.com/cyanheads/mcp-ts-core/issues/264)
- **Outline-on-overflow docs** — `OUTLINE_VARIANT` / `outlineOnOverflow()` JSDoc and the `techniques`, `add-tool`, and `design-mcp-server` skills corrected: a tool's `output` is a flat `z.object` with a `kind` discriminator and presence-based optional arms (fold in `OUTLINE_VARIANT.shape.sections` / `.notice`), not the `z.discriminatedUnion` output `tool()` rejects, and `format()` renders each arm on field presence. Docs and JSDoc only — no runtime change. [#249](https://github.com/cyanheads/mcp-ts-core/issues/249)
- **`release-and-publish` skill GHCR verify** — the reachability check uses `docker manifest inspect ghcr.io/<owner>/<repo>:<version>` instead of a bare-token `curl`, which 404s on the multi-arch OCI indexes `docker buildx` pushes (no `Accept` header for manifest lists). [#262](https://github.com/cyanheads/mcp-ts-core/issues/262)
