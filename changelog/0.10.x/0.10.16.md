# 0.10.16 — 2026-07-26

## Added

- **`runDetached`** exported from `/utils` — runs a function under `ROOT_CONTEXT`, with no active span. Register long-lived listeners (server sockets, streams) through it: the OTel context manager is AsyncLocalStorage-backed, so a store captured at listener creation propagates to every request that listener later serves. [#294](https://github.com/cyanheads/mcp-ts-core/issues/294)
- **`MCP_LOG_RATE_LIMIT_THRESHOLD`** (default `10`, `0` disables) and **`MCP_LOG_RATE_LIMIT_WINDOW_MS`** (default `60000`) — the logger's rate limit is now configurable instead of hardcoded. [#295](https://github.com/cyanheads/mcp-ts-core/issues/295)

## Changed

- **`devcheck` outdated gate** — a row whose `Update` equals `Current` no longer fails the gate: nothing is installable under the declared range, whether because `minimumReleaseAge` holds a fresh publish or because the range deliberately caps below latest. `(peer)` rows are skipped too; a peer range declares the lowest supported version, and currency for what is actually exercised comes from the matching devDependency row.
- **`templates/devcheck.config.json`** — `typescript` added to the `outdated` allowlist, matching the framework's own deliberate hold on the 7.x major.

## Fixed

- **`MCP_AUTH_MODE=none` no longer advertises OAuth** — `/.well-known/oauth-protected-resource` and its RFC 8414 §3 path-suffixed variant are mounted only when an auth mode is configured. Serving that document declares the server a protected resource, sending a discovering client into an OAuth flow with no `authorization_servers` to register with; the 404 is the signal that the resource is unauthenticated. `jwt` and `oauth` are unaffected. [#293](https://github.com/cyanheads/mcp-ts-core/issues/293)
- **Transport bind runs detached from the startup span** — `createApp` wraps `transportManager.start()` in `runDetached`, so the `mcp.server.startup.transport` span still times the bind but no longer leaks into the listener's ALS store. An ended span still carries a valid `SpanContext`, so without this every later request inherits its `traceId` and parent `spanId` for the process lifetime. [#294](https://github.com/cyanheads/mcp-ts-core/issues/294)
- **Logger rate limiting no longer truncates per-call logs** — the limit keys on level + message rather than the message alone, and the framework's per-call telemetry lines (`Tool execution finished.`, `Resource read finished.`, prompt generation) bypass it entirely; their message strings are constant by design, so a busy server was capping log-derived call volume at the threshold. Message constants live in `src/utils/internal/telemetryMessages.ts`, shared by the emitter and the limiter so the two cannot drift. [#295](https://github.com/cyanheads/mcp-ts-core/issues/295)
- **Suppression notices emit at `warning`** — previously `debug`, which is filtered out at exactly the levels where lines are being dropped, leaving a truncated log that reads as a quiet one. The notice names the suppressed level + message, the count, and the active threshold and window. The pending map is snapshotted and cleared before emitting, since each notice re-enters `log()`.
- **`data/` anchored to `/data/`** in `.gitignore` and `templates/_.gitignore` — the unanchored pattern also matched `src/data/` and `tests/fixtures/data/`, silently untracking bundled source and test fixtures. `dist/data` stays ignored via `dist/`. [#287](https://github.com/cyanheads/mcp-ts-core/issues/287)
- **Fresh scaffold passes `devcheck`** — `templates/devcheck.config.json` ignores `@socketsecurity/bun-security-scanner` in depcheck. It is wired through `bunfig.toml` as an install-time scanner and never imported, so depcheck flagged it as unused. [#270](https://github.com/cyanheads/mcp-ts-core/issues/270)
- **Production Docker stage stays production-only** — the OTEL `bun add` in `Dockerfile` and `templates/Dockerfile` carries `--omit=dev --ignore-scripts`. Without them it re-resolved the full manifest, pulling the dev toolchain back into the final image and undoing the preceding `--production` install. [#283](https://github.com/cyanheads/mcp-ts-core/issues/283)
