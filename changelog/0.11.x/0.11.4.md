# 0.11.4 — 2026-08-10

## Added

- **`schema-unsatisfiable`** (error) ([#310](https://github.com/cyanheads/mcp-ts-core/issues/310)). Flags any node in the emitted JSON Schema that describes an empty value set — `enum: []`, `anyOf: []`, `oneOf: []`, `type: []`, `not: {}` — a field no value can ever satisfy, which nothing downstream reported: the tool registered, the schema reached the model, and the argument could never be populated. Evaluated on the emitted schema rather than on Zod internals because the two disagree in the case that matters: `z.enum([1, 2, 3])` keeps its options on the Zod side and serializes to `{"type":"string","enum":[]}`. Runs on tool `input`/`output`, resource `params`/`output`, and prompt `args`. Not flagged: `allOf: []` (vacuously true) and empty `required`/`properties`/`prefixItems`, which are absent constraints rather than impossible ones.
- **`format-parity-depth-limit`** (warning) ([#280](https://github.com/cyanheads/mcp-ts-core/issues/280)). The sentinel walker's depth-8 bail now names the schema path it declined to descend into. The bail returned a state indistinguishable from a field that resolved to nothing, so an unevaluated subtree read as a pass; four array hops from the output root is enough to reach the bound.
- **`fast-check`** — scaffold `devDependency` (`^4.9.0`) ([#316](https://github.com/cyanheads/mcp-ts-core/issues/316)). `templates/tests/fuzz/echo-tool.fuzz.test.ts` reaches it through the framework's optional peer, which is not installed for you, so a fresh scaffold failed its first test run on `Cannot find package 'fast-check'`.

## Changed

- **Every linter change below removes a false negative.** A server carrying a latent gap goes red on its next `lint:mcp`/`devcheck` after upgrading; definition linting is build-time only, so nothing already deployed changes behavior. Newly errors: `schema-unsatisfiable`, plus format parity on multi-value literals and on enum/literal/boolean leaves whose value only appeared as an incidental substring. Newly warns: `format-parity-depth-limit` past depth 8, and `capped-list-no-truncation` on cap names outside the old allowlist.
- **The format-parity string sentinel is alphanumeric** ([#337](https://github.com/cyanheads/mcp-ts-core/issues/337)). `MCPPARITY<path>`, with the path's non-alphanumerics folded to `Q` so distinct paths keep distinct sentinels. The old `__MCP_PARITY_…__` form did not survive a `format()` that escapes markdown — `\_\_MCP\_PARITY…` is a correct escape and was read as an unrendered field, so a server had to carve `_` out of its escape set to keep the rule green. An alphanumeric run is inert under markdown escaping, HTML escaping, and URL encoding alike, so the matcher needs no branch per convention.
- **Schema-dictated parity sentinels match as delimited tokens** ([#282](https://github.com/cyanheads/mcp-ts-core/issues/282)). Enum members, literals, booleans, and the unrecognized-type fallback must now appear un-flanked by another alphanumeric or `_`. A short natural-word member (`full`, `all`, `none`) matched incidental output — including a sibling leaf's rendered sentinel — so a required discriminator `format()` never rendered passed parity. An enum leaf's sample has to stay a legal member of its enum, so the fix is the match strategy, not the injected value. Strict string and number leaves keep plain substring matching, and the key-name fallback is unchanged.
- **`capped-list-no-truncation` matches cap names by shape** ([#278](https://github.com/cyanheads/mcp-ts-core/issues/278)). `isCapFieldName` replaces the enumerated `CAP_FIELD_RE`: camelCase normalizes to snake_case first, then `limit`, `<noun>_limit`, `max_<noun>`, and the `per_page`/`page_size` idioms match. An enumeration turned every new cap noun into a silent gap where the rule never ran at all — the defect class the rule exists to catch. Bare `count`, `size`, `n`, `rows`, and `records` still do not match. The shape cannot separate a cap on how many from an upper bound on a value, so a range filter spelled `max_<noun>` matches too; `truncationAllowlist` exempts a tool that trips it.
- **`OutlineOptions.notice` receives the budget** ([#328](https://github.com/cyanheads/mcp-ts-core/issues/328)). Signature widened to `(sections, budget) => string`; a single-argument callback is unaffected. The default names the largest section that *fits* the budget with its byte size inline, instead of the three largest — which, since sections arrive sorted largest-first, was by construction the most expensive retrieval available and the one most likely to overflow the budget the outline exists to enforce. When no single section fits, it names none and points at narrowing the request. One section, not several: sizes are per-section, so a multi-section example would advertise a combination that may not fit.
- **The scaffolded `tsconfig` splits typecheck from emit** ([#316](https://github.com/cyanheads/mcp-ts-core/issues/316)). `tsconfig.json` covers `src/` and `tests/` with `rootDir: "."` and `noEmit: true`, plus an explicit `tsBuildInfoFile: ".tsbuildinfo"` — without it the `--noEmit` run writes its incremental cache into `outDir` and `files: ["dist/"]` publishes it. `tsconfig.build.json` carries `rootDir: "src"`, `include: ["src/**/*"]`, and `noEmit: false`, so the build path is unchanged. A scaffolded server's tests never reached `tsc` before, and could drift from the schemas they exercise with every gate green. The starter tests were updated for the contracts they exercise: `createMockContext({ errors: echoTool.errors })`, awaited `generate`/`list`, and non-null `args`/`params` accesses.
- **The production Docker stage omits optional peers** ([#317](https://github.com/cyanheads/mcp-ts-core/issues/317)). `--omit=peer` rides the production `bun install` and the OTEL `bun add`, in `templates/Dockerfile` and in this repo's own `Dockerfile`. `--production`/`--omit=dev` do not omit optional peers — Bun auto-installs them — so the runtime image shipped the framework's opt-in tiers, a test runner and several service SDKs among them. The second flag is load-bearing: without it the OTEL step re-resolves the graph and pulls them back in. An optional tier a server actually uses is a direct dependency of that server, never something inherited from the framework's peer list.

## Fixed

- **format-parity walks a multi-value literal** ([#310](https://github.com/cyanheads/mcp-ts-core/issues/310)). The `literal` case read the instance getter, and Zod 4's `.value` throws on `z.literal([1, 2, 3])`, so the rule reported `format-parity-walk-failed` and disabled parity for that whole definition — the idiomatic way to advertise a closed non-string set as one schema node. It now reads `_zod.def.values`, a plain array for single- and multi-value literals alike. Guarding the getter is not enough: the instance `.values` is a `Set`, so an index read yields `undefined` and falls through to the throwing `.value`.
- **Enrichment trailer fields stay out of the preceding container** ([#308](https://github.com/cyanheads/mcp-ts-core/issues/308)). Fields were joined by a bare `\n`, and CommonMark lazy continuation folds an unprefixed line into an open block quote or list item — so a `total` or `echo` enriched after a `notice` rendered as quoted text attributed to that notice. A field whose last line opens a quote (`>`) or a list item (`-`, `+`, `*`, `1.`, `1)`, indented up to three spaces) is now followed by a blank line; every other field keeps the compact single-`\n` layout. The test is the line, not the field kind, so a custom `enrichmentTrailer.render` whose output ends in a bullet terminates the same way. A list marker must be followed by a space or end the line, so `**0 total**` and a `***` rule are not mistaken for bullets.
- **`scripts/tree.ts` honors directory-only gitignore patterns** ([#304](https://github.com/cyanheads/mcp-ts-core/issues/304)). `ignore` decides a path is a directory from a trailing slash on the path it is given, so a pattern written as `/data/` or `.claude/` matched nothing and the directory was listed in the generated `docs/tree.md` — contradicting that file's own footer. `isIgnored` takes the flag from the `Dirent` the call site already holds. Regenerating this project's tree drops `.agents/`, `.claude/`, `agent-feedback/`, `announcements/`, and `tmp/`.
- **The fuzz leak heuristic ignores the input's own strings.** `recordLeak` strips every string the generated input carried — object keys included, and their JSON-escaped forms, longest needle first — before checking the client-visible error text for a stack frame or server-side path. A handler that names the offending value in its error data, the pattern the framework recommends, handed the fuzzer its own generated string back; a generated string carries a `<letter>:\` trigram about once in six thousand, which is enough to fail a suite intermittently and nowhere near often enough to reproduce by rerunning it.
