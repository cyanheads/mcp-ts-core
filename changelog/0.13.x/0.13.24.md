# 0.13.24 — 2026-11-26

## Changed

- **Skills** — `add-service` 1.14, `add-test` 1.11, `add-tool` 2.40, `api-canvas` 2.17, `api-config` 1.34, `api-context` 2.20, `api-errors` 1.30, `api-linter` 1.26, `api-telemetry` 1.26, `api-testing` 1.19, `api-utils` 2.25, `api-workers` 1.15, `field-test` 2.28. `add-tool` § Feature-flagged tools and `api-config` § When `.env` loads cover the import-time gate; `api-errors`, `api-testing`, and `api-utils` follow the fixes below; code samples across these skills use Biome's import order.

## Fixed

- **Server config read before `createApp()` (a module-scope `disabledTool()` gate, a `z.lazy` bound) sees `./.env` under Node as under Bun** ([#634](https://github.com/cyanheads/mcp-ts-core/issues/634)). `parseEnvConfig` and `composeServices()` share framework config's one-time load. A `.env` that exists but cannot be loaded (a symlink into an unsearchable directory included) stops startup with the `Failed to load .env from the working directory.` banner, even when `resetConfig(overrides)` cached the config.
- **`MCP_LOG_LEVEL` defaults to `info`, not `debug`** ([#705](https://github.com/cyanheads/mcp-ts-core/issues/705)), the default every doc states.
- **A service throw of a declared `reason` carries the entry's `retryable` as `data.retryable`**, as `ctx.fail` does, when the throw sets none, with or without its own `recovery` ([#856](https://github.com/cyanheads/mcp-ts-core/issues/856)). `runToolContract` resolves argument rejections against `errors[]` as the handler factory does.
- **`mapError` string patterns match as literal, case-insensitive substrings** ([#676](https://github.com/cyanheads/mcp-ts-core/issues/676)): `'$5'` matches, `'foo('` and `'C++'` no longer throw, `'a.b'` no longer matches `axb`. A string used as a regex now matches only that text. The pattern cache keeps strings and `RegExp`s apart, and a `RegExp`'s `y` flag is dropped as `g` is.
- **`runToolContract` rejects with the input-required signal when a handler calls `ctx.requestInput(...)`**, as production returns an `input_required` result ([#667](https://github.com/cyanheads/mcp-ts-core/issues/667)). Assert a round with `expectInputRequired(() => runToolContract(...))`. The fuzz helpers count it as a completed call, and `fuzzTool` parses a handler's return with `parseToolOutput`.
- **`toolContractSuite` success cases no longer re-parse `structuredContent` against `output`** ([#668](https://github.com/cyanheads/mcp-ts-core/issues/668)), so a strict `output` root beside `enrichment`, a `z.stringbool()` field, and a `.transform()` or `.pipe()` field pass as they do on the wire.
- **`decodeCursor` rejects an `offset` or `limit` that is not a safe integer** as `invalid_cursor` ([#611](https://github.com/cyanheads/mcp-ts-core/issues/611)). `encodeCursor` throws `InternalError` for a state the decoder would refuse, such as a fractional page size passed to `paginateArray`.
- **The `invalid_cursor` recovery hint no longer names `nextCursor`** ([#603](https://github.com/cyanheads/mcp-ts-core/issues/603)): it points at the next-page cursor from the previous response, and `literals` is `['cursor']`.
- **`decodeCursor` echoes a rejected cursor longer than 50 characters as its first 50 and `...`** in `data.cursor` and its warning record ([#873](https://github.com/cyanheads/mcp-ts-core/issues/873)). The cut ends a unit early rather than split a surrogate pair, and `validateKey`, `validatePrefix`, and the KV/R2 stored-name check cut the same way.
- **`disabledTool()` keeps the strictening record**, so `lint:mcp` reports `schema-root-meta-discarded` for a disabled tool as for the original ([#688](https://github.com/cyanheads/mcp-ts-core/issues/688)).
- **`devcheck`'s TODOs/FIXMEs, Framework Antipatterns, and Tracked Secrets steps cover untracked files**, so a new file fails before it is added ([#885](https://github.com/cyanheads/mcp-ts-core/issues/885)). `devcheck.config.json` `todos.ignore` lists pathspecs the TODOs/FIXMEs step skips.
- **A fresh `init` scaffold is Biome-clean**, so the first `devcheck` rewrites no file ([#557](https://github.com/cyanheads/mcp-ts-core/issues/557)). `test:package` asserts the scaffold's `Biome` step `PASSED`.
- **Files `init` copies into a server cite framework issues as `cyanheads/mcp-ts-core#N`**, not a bare `#N` ([#721](https://github.com/cyanheads/mcp-ts-core/issues/721)): `templates/.env.example`, the changelog template's example, the shipped scripts' comments, and `field-test`.
