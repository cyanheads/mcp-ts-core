# 0.13.18 — 2026-10-25

## Added

- **`createApp({ skills })`** ([#789](https://github.com/cyanheads/mcp-ts-core/issues/789)): serves a folder of skill folders (conventionally `skills`) over MCP through the SEP-2640 Skills extension on both protocol eras. A relative path resolves against the application root; a missing folder fails startup with `ConfigurationError`, and a skill the SDK rejects is skipped with a logged warning.
- **`createWorkerHandler({ skills })`** ([#789](https://github.com/cyanheads/mcp-ts-core/issues/789)): the same tree as a record of paths to file contents, built from Wrangler `Text` imports.
- **Root `skills/` is the published, agent-facing tree** ([#429](https://github.com/cyanheads/mcp-ts-core/issues/429)): opt-in and author-managed, separate from `framework-skills/`. The new `add-skill` skill covers when one earns its place and how to write it.
- **`validateSkillTree(root)` from `@cyanheads/mcp-ts-core/linter`** ([#429](https://github.com/cyanheads/mcp-ts-core/issues/429)): runs the MCP SDK's strict skill loader and returns `{ path, message }[]`.
- **`lint:packaging` check 17** ([#429](https://github.com/cyanheads/mcp-ts-core/issues/429)): root `skills/` must pass `validateSkillTree` plus project rules (`description` at most 500 characters, `SKILL.md` at most 150 lines, no `metadata.audience: external`), and no `.mcpbignore` pattern may strip it.
- **`templates/plugin.json` and `templates/mcp.json`** ([#426](https://github.com/cyanheads/mcp-ts-core/issues/426)): the Agent Plugins 1.0.0 root pair, scaffolded by `init`. `lint:packaging` check 10 validates the pair when root `plugin.json` exists.

## Changed

- **Enrichment trailer string values render as code literals** ([#785](https://github.com/cyanheads/mcp-ts-core/issues/785)): `echo`, `delta`, and generic lines show a string, and an object's JSON, as a code span, or as a fenced block on its own lines when the value has a line break, so a copied query, cursor, or SQL carries no backslashes. An empty string renders as nothing.
- **The scaffold `.mcpbignore` excludes build-only and repo-local root paths** ([#508](https://github.com/cyanheads/mcp-ts-core/issues/508)), all root-anchored; `lint:packaging` check 5 requires each line and check 6 rejects an unanchored form.
- **`clean-mcpb` strips node-gyp build output** beside a `binding.gyp` ([#783](https://github.com/cyanheads/mcp-ts-core/issues/783)) **and build-only package files** ([#791](https://github.com/cyanheads/mcp-ts-core/issues/791)): the framework's `changelog/`, `config/`, `scripts/`, `templates/`, `CLAUDE.md`, `AGENTS.md`, `biome.json`, `vitest.config.base.mjs`, and `better-sqlite3`'s `deps/` and `src/`. Compiled `*.node` addons stay; check 8 reports any left in a built bundle.
- **`check-skills-sync` reads only the `SKILL.md` frontmatter** for `audience: external`, and `devcheck` runs the packaging check whenever root `skills/` exists.
- **`templates/Dockerfile` creates and copies `skills/`**, and `templates/package.json` lists it in `files`.
- **Skills** — `add-skill` 1.0 (new), `add-tool` 2.37, `api-canvas` 2.11, `api-context` 2.15, `api-utils` 2.20, `api-workers` 1.11, `design-mcp-server` 2.34, `field-test` 2.25, `git-wrapup` 1.32, `maintenance` 2.11, `polish-docs-meta` 2.26, `setup` 1.13.

## Fixed

- **`escapeMarkdownInline` escapes the last `#` of a trailing ` #` run** ([#781](https://github.com/cyanheads/mcp-ts-core/issues/781)) (`abc #` → `abc \#`), which an ATX heading dropped as its closing sequence. Leading and trailing whitespace of every Unicode kind becomes a numeric reference, not only space and tab.
- **The bare `current_schema` canvas refusal states DuckDB's binding** ([#784](https://github.com/cyanheads/mcp-ts-core/issues/784)): the message says an unqualified name reads as the function unless a column of that name is in scope, and the recovery hint says to qualify the column (`<table>.current_schema`). The `denied_function` reason is unchanged.
