# 0.13.23 — 2026-11-26

## Changed

- **`fetchWithTimeout` records timeouts (`FetchTimeout`, `FetchSignalTimeout`) and network failures (`FetchNetworkError`) at `info`, not `error`** ([#864](https://github.com/cyanheads/mcp-ts-core/issues/864)). A failure the caller retries or handles leaves no `error` record; one that escapes a tool, resource, or prompt handler is still logged at `error` by its factory.
- **Test tooling moves to Vitest 5.1.2** ([#420](https://github.com/cyanheads/mcp-ts-core/issues/420)). The Workers lanes run on `@cloudflare/vitest-plugin` with `wrangler` as a direct dev dependency, and the microbenchmarks use the `bench` fixture and read `BENCH_OUTPUT_DIR` / `BENCH_BASELINE_DIR` in place of `--outputJson` / `--compare`.
- **Scaffolds require `vitest` and `@vitest/coverage-istanbul` `^5.1.2` and set `[run] bun = true` in `bunfig.toml`** ([#882](https://github.com/cyanheads/mcp-ts-core/issues/882)), so `bun run test` runs Vitest on Bun. `.vitest/` joins the scaffold's `.gitignore`; its `.mcpbignore` gains `/.vitest/` and `/node_modules/.vitest-cache/`.
- **The `@duckdb/node-api` peer range admits `^2.0.1-r.1`.**
- **Skills** — `api-canvas` 2.16, `api-config` 1.33, `api-errors` 1.29, `api-mirror` 1.11, `api-testing` 1.18, `api-utils` 2.24, `api-workers` 1.14, `field-test` 2.27, `git-wrapup` 1.34, `orchestrations` 1.16, `polish-docs-meta` 2.28, `release-and-publish` 2.27, `release-pr-review` 1.10, `security-pass` 1.17, `tool-defs-analysis` 1.10. `field-test`, `security-pass`, and `tool-defs-analysis` write their plan out and use a task tool only when the harness offers one; `orchestrations` adds a plan-overview step before the first work phase; `api-config` and the scaffold's `CLAUDE.md` list the full `z.stringbool()` vocabulary (`y/n`, `enabled/disabled`); `polish-docs-meta` § `bunfig.toml` points at `templates/_bunfig.toml`.

## Fixed

- **Opening a SQLite mirror store no longer takes the write lock to re-seed the sync rows** ([#895](https://github.com/cyanheads/mcp-ts-core/issues/895)). `mirror_sync_state` and `mirror_sync_lease` are seeded only when a row is missing, so a store at its spec's version opens and reads while another connection holds a write transaction.
- **A mirror record supplies a column only through its own property** ([#844](https://github.com/cyanheads/mcp-ts-core/issues/844)). A column named after an `Object.prototype` member (`constructor`, `toString`) or `__proto__` stores NULL when the record omits it instead of failing the write, and a getter inherited from a class supplies nothing.
- **A function or symbol in a mirror record, tombstone, `getByIds` id, filter value, `in` list, or `match` rejects with `ValidationError`** naming where it sat, not a raw driver `TypeError`.
- **`createPacer` sheds a queued caller at once as `wait_projected` when a cooldown closes the gate past its `maxWaitMs`**, instead of holding it until the budget runs out and shedding it as `wait_elapsed` ([#892](https://github.com/cyanheads/mcp-ts-core/issues/892)). A caller that can still start in time keeps its place.
- **Cancelling a 2xx `fetchWithTimeout` body while a read is in flight no longer logs `Network error during fetch …: Controller is already closed`** ([#854](https://github.com/cyanheads/mcp-ts-core/issues/854)).
- **A `fetchWithTimeout` caller signal that aborts with a `TimeoutError` throws `<operation>: <reason message>`** (`<operation> timed out.` when the message is empty), not `… timed out on the caller's signal.` ([#878](https://github.com/cyanheads/mcp-ts-core/issues/878)).
- **`escapeMarkdownInline` and the tool-error encoder built on it keep working memory proportional to the output** ([#887](https://github.com/cyanheads/mcp-ts-core/issues/887)); the output is unchanged.
- **`escapeMarkdownInline` escapes the first `#` of a line made only of `#`**, so seven or more `#` read back as text, not an ATX heading's closing sequence (`#######` → `\#######`) ([#879](https://github.com/cyanheads/mcp-ts-core/issues/879)).
- **The stdio transport writes U+2028 and U+2029 as JSON escapes**, so a `node:readline` client reads one line per message ([#868](https://github.com/cyanheads/mcp-ts-core/issues/868)).
- **Destroying a canvas with calls in flight no longer crashes the process or fails the call** ([#893](https://github.com/cyanheads/mcp-ts-core/issues/893)) — `DataCanvas.drop()`, the sweeper's TTL and absolute-cap pass, a rolled-back create, and `shutdown()`. A later call rejects `canvas_not_found`; the engine closes and the spill directory goes once the running calls settle, and the scratch directory `shutdown()` removes goes only after those closes.
- **Each canvas engine on `@duckdb/node-api` 2.x runs DuckDB's asynchronous I/O pool on one thread (`async_threads: '1'`)** instead of four per detected thread ([#870](https://github.com/cyanheads/mcp-ts-core/issues/870)). 1.5.x refuses the option and gets none.
- **A table or view named after a DuckDB system view (`duckdb_views`, `sqlite_master`, `pg_class`) stages through `registerTable`, `query({ registerAs })`, `registerView`, and `importFrom({ asName })`** and leaves the canvas working ([#862](https://github.com/cyanheads/mcp-ts-core/issues/862)). Catalog reads use `duckdb_tables()`, `duckdb_views()`, and `duckdb_columns()` instead of `information_schema`.
- **`query({ registerAs })` that races another registration of the name, or names a staged table or view in another letter case, rejects `register_as_clash`** (`data.tableName`) instead of a raw `DatabaseError`, and a losing call never drops the winner's table ([#891](https://github.com/cyanheads/mcp-ts-core/issues/891)). `register_as_clash` and `view_table_clash` carry a recovery hint.
- **Canvas errors that quote a table or view name (`missing_table`, `register_as_clash`, `view_table_clash`, `import_view_clash`, `view_unreadable`) pass it as `literals`**, so `content[]` renders a code span, not backslash-escaped text ([#863](https://github.com/cyanheads/mcp-ts-core/issues/863)).
- **Canvas registration races reject typed**: `registerTable` against a same-name registration rejects `DatabaseError`; `registerView()` onto a name a table takes, or a table name in another letter case, rejects `view_table_clash`; `importFrom()` onto a view whose name differs only in letter case rejects `import_view_clash`. Each was a raw error.
- **The `sql_execution_error` hint for an `Invalid Input Error` covers a constant argument a function rejects only as it runs** (a regex pattern on DuckDB 2.0, a `format` string), and a prepare-time `Conversion Error` gets that hint instead of the column hint.

## Security

- **On the stdio transport, console output goes to stderr** ([#859](https://github.com/cyanheads/mcp-ts-core/issues/859)). `startStdioTransport` rebinds the console to a `Console` over stderr for the life of the process, `console.write` included on Bun, so console output from a handler or a dependency (`htmlExtractor`'s `debug` log among them) never reaches the JSON-RPC stream on stdout. `createApp` routes it before core services start and `setup()` runs. HTTP and Workers are unchanged.
- **`fetchWithTimeout` follows redirects itself on every request, so Node, Bun, and workerd handle a chain alike** ([#883](https://github.com/cyanheads/mcp-ts-core/issues/883)): up to 127 hops, 5 under `rejectPrivateIPs`. A hop to another origin drops `Authorization`, `Cookie`, `Proxy-Authorization`, and a caller-set `Host`; a 301 or 302 for a `POST`, and a 303 for any method but `GET` or `HEAD`, continue as a bodiless `GET`. A redirect loop fails `too_many_redirects` and a non-HTTP(S) target `invalid_url` (both `ValidationError`); a 3xx under `redirect: 'error'` without `rejectPrivateIPs`, or any 3xx but a 303 answering a stream body, fails `InvalidRequest`. `withRetry` retries none of them.
