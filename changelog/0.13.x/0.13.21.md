# 0.13.21 — 2026-11-06

## Added

- **`createApp({ decodeResourceParams: true })`** ([#490](https://github.com/cyanheads/mcp-ts-core/issues/490)), also on `createWorkerHandler`: percent-decodes each matched resource-template variable once before `params` validation; a malformed escape answers the `params` rejection shape. Default off; `ctx.uri` and completion arguments are unchanged.
- **`describe()` columns carry `engineType`** ([#500](https://github.com/cyanheads/mcp-ts-core/issues/500)): the engine's type verbatim (`DECIMAL(10,2)`, `BIGINT[]`). `TableInfo.columns` is typed `DescribedColumn[]`; `engineType` is optional, so a hand-built `TableInfo` still compiles.
- **`describe()` accepts `signal`**, and a describe in progress no longer blocks other calls on the canvas.

## Changed

- **Skills** — `add-resource` 1.9, `api-auth` 1.9, `api-canvas` 2.14, `api-config` 1.31, `api-context` 2.18, `api-errors` 1.27, `api-mirror` 1.9, `api-testing` 1.17, `api-utils` 2.22, `api-workers` 1.12.

## Fixed

- **`MCP_HTTP_ENDPOINT_PATH` is normalized once** ([#830](https://github.com/cyanheads/mcp-ts-core/issues/830)): a leading `/` is added, whitespace trimmed, dot segments resolved, and percent-encoding decoded as the router decodes a request path. A value with no single reading (a full URL, `?`, `#`, inner whitespace, a malformed escape, a backslash, a path resolving to `//…`, router pattern syntax) fails startup with a `ConfigurationError` that does not echo it.
- **`MCP_PUBLIC_URL` must be an `http` or `https` base URL with no query, fragment, or user info** ([#831](https://github.com/cyanheads/mcp-ts-core/issues/831)); anything else fails startup with a `ConfigurationError` that does not echo the value. The landing page renders the same serialized URL as the server card and the protected-resource metadata.
- **Every trailing slash of `MCP_PUBLIC_URL` is dropped once**, so the server card, the protected-resource metadata's `resource`, and the `401` challenge's `resource_metadata` name the same URL.
- **HTTP error responses echo the request's JSON-RPC `id`** whenever the body was read ([#685](https://github.com/cyanheads/mcp-ts-core/issues/685)), the `503` at session capacity included.
- **`initialize`, the server card, and the landing page report one server description** ([#683](https://github.com/cyanheads/mcp-ts-core/issues/683)): the `createApp` option, then `MCP_SERVER_DESCRIPTION`, then the server's own `package.json`. A server with none advertises none.
- **A handler's SDK `ProtocolError` keeps its code, message, and object `data` on tools, prompts, and resources** ([#828](https://github.com/cyanheads/mcp-ts-core/issues/828)). A `UrlElicitationRequiredError` (`-32042`) goes back to the SDK on all three, and `runToolContract` rejects with that `ProtocolError`.
- **A resource read that throws a URL elicitation no longer puts `-32042` on the wire for a 2026-07-28 client**; the SDK answers it in that revision's form.
- **A resource handler's legacy not-found `ProtocolError` (`-32002`) answers in the not-found shape** ([#829](https://github.com/cyanheads/mcp-ts-core/issues/829)), `data` exactly `{ uri }` when the error carries a string `uri`.
- **`resources/list` entries a template's `list` callback returns carry a `title` only when the entry sets one** ([#690](https://github.com/cyanheads/mcp-ts-core/issues/690)); the other inherited fields are unchanged.
- **D1 `list` takes a prefix of any length and matches it exactly** ([#832](https://github.com/cyanheads/mcp-ts-core/issues/832), [#655](https://github.com/cyanheads/mcp-ts-core/issues/655)): the prefix is a key range, so keys that differ only in case no longer match.
- **KV `get` keeps a backend failure's own error class** ([#658](https://github.com/cyanheads/mcp-ts-core/issues/658)): the value is read as text and parsed locally, so only a value that is not JSON is a `SerializationError`. The unsupported methods of the ElevenLabs (speech-to-text) and Whisper (text-to-speech, voice listing) providers return a rejected promise instead of throwing.
- **Mirror whole numbers bind as INTEGER on Node and Bun** ([#833](https://github.com/cyanheads/mcp-ts-core/issues/833)), through the store and `raw()` parameters: a safe integer other than `-0` reaches a TEXT, BLOB, or untyped column as `2024` on both.
- **Mirror `raw()` binds alike on Bun and Node** ([#834](https://github.com/cyanheads/mcp-ts-core/issues/834)): `ArrayBuffer`, `SharedArrayBuffer`, and `DataView` bind as a blob, and named-parameter values and array elements get the mapping positional values get (the caller's object is not changed).
- **Mirror `get()` returns `undefined` for no row on Bun and Node** ([#780](https://github.com/cyanheads/mcp-ts-core/issues/780)), for `SELECT` and `… RETURNING` alike.
- **A mirror `in` filter binds its list as one parameter** ([#835](https://github.com/cyanheads/mcp-ts-core/issues/835)), so its length is bounded only by the store's own limits; byte values still bind one parameter each.
- **Mirror schema and query validation** ([#666](https://github.com/cyanheads/mcp-ts-core/issues/666)): an inherited object property (`constructor`, `toString`) named as primary key, FTS column, or index column is a `ConfigurationError` when the store is built; an unknown filter `op` and a malformed `MATCH` query are `ValidationError`s.
- **Mirror `getByIds` matches an id against the key across number and string**, as an `eq` filter does. A bigint id outside the signed 64-bit range, an array given to a scalar filter operator, and a `sort.direction` other than `asc` or `desc` are `ValidationError`s.
- **A sync stopped by the caller's signal logs "Mirror sync stopped" at `info`** ([#813](https://github.com/cyanheads/mcp-ts-core/issues/813)) with the mode and the abort reason. The stored state record is unchanged, and a source's own timeout still logs as a failure.
- **`describe()` rejects once for unreadable views** ([#838](https://github.com/cyanheads/mcp-ts-core/issues/838)): after reading every object in scope, a `ValidationError` with `data.reason: 'view_unreadable'`, `data.views` listing each as `{ name, engineMessage }`, and a hint to drop or redefine it. `drop()` reports an engine failure as a classified error.
- **`describe()` tags `TINYINT`, `SMALLINT`, `UTINYINT`, and `USMALLINT` as `INTEGER` and `UINTEGER` as `BIGINT`** (all were `VARCHAR`); a list or array of timestamps tags `VARCHAR` like every other list (was `TIMESTAMP`).
- **A canvas path export writes a staging file beside the target (`.<name>.<UUID>.partial`) and renames it over the target once written** ([#740](https://github.com/cyanheads/mcp-ts-core/issues/740)); a call that rejects removes the staging file and leaves the target as it found it. Errors name the requested path.
- **Canvas reads that do not open with `SELECT`, `WITH`, or `FROM`** (`SHOW`, `DESCRIBE`, `SUMMARIZE`, `VALUES`, `TABLE`, a parenthesized select) report `missing_table` (with `tableName`) or the binder detail as a `SELECT` does ([#597](https://github.com/cyanheads/mcp-ts-core/issues/597)); the statements the gate admits are unchanged. A `PIVOT` without an `IN` list is refused with `non_select_statement` on both DuckDB lines (DuckDB 1.5 reported `multi_statement`) and a hint naming the `ON column IN (value, ...)` form.
- **Parquet `export()` and `importFrom()` write as a single writer in capped row groups** ([#836](https://github.com/cyanheads/mcp-ts-core/issues/836)). A Parquet export now holds one 2,048-row slice of the table plus the writer's buffers, as CSV and JSON exports do; a table whose 2,048 widest rows do not fit beside them inside the canvas memory limit still fails, now with a typed error. A Parquet export of a large narrow table takes roughly three to five times as long on a many-core host; the rows, row order, and schema are unchanged, and a Parquet stream export writes the same way.
- **A canvas export that runs out of memory is a `DatabaseError` with `data.reason: 'export_out_of_memory'` and `data.format`** ([#826](https://github.com/cyanheads/mcp-ts-core/issues/826)), the first line of the engine message, and a per-format sizing hint; `api-canvas` gains the JSON sizing line. DuckDB's tuning advice is cut from out-of-memory messages on `query()` and `registerTable()`.
- **`registerTable()` reports an engine failure while its rows are written as a `DatabaseError`** with the engine error on `cause` (was a raw `Error`). The caller's own row-source error and a cancellation reach the caller unchanged, and the previous table is kept.
- **`export()` and `importFrom()` of a view whose table was dropped report `missing_table`** as `query()` does; an `importFrom()` whose source is dropped between its lookup and its copy rejects with the missing-source `NotFound`.
- **Missing optional-peer messages name the package and say to add it to the server's dependencies** ([#814](https://github.com/cyanheads/mcp-ts-core/issues/814)), with no package manager named; error class, code, and `data` are unchanged.
- **`pdfParser.extractText` reads caller-supplied bytes from a copy**, so the caller's buffer is unchanged and a Node `Buffer` is accepted. The call holds one extra copy of the input while it runs, inside the input budget.

## Security

- **A Worker's string bindings now reach every configuration variable that has an effect on a Worker, including `MCP_JWT_EXPECTED_AUDIENCE` and `MCP_JWT_EXPECTED_ISSUER`** ([#837](https://github.com/cyanheads/mcp-ts-core/issues/837)); `extraEnvBindings` still adds server-specific names.
- **On Cloudflare Workers, `DEV_MCP_AUTH_BYPASS` is honored only when the environment is explicitly non-production: `ENVIRONMENT` (or `NODE_ENV`) set to `development` or `testing`.** A Worker dev setup that uses the bypass sets `ENVIRONMENT=development` in its `[vars]`; without it the Worker fails with a `ConfigurationError` naming both variables. Node and Bun servers are unchanged.
