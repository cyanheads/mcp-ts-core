# 0.13.16 — 2026-10-24

## Added

- **`escapeMarkdownInline`, `markdownLink`, and `markdownImage` export from `/utils`** ([#758](https://github.com/cyanheads/mcp-ts-core/issues/758)): they encode text the tool did not author so a CommonMark parse of `content[]` reads it back as written. Only an absolute `http:` or `https:` URL renders as a link or image; anything else renders as literal `text (url)`.

## Changed

- **Out-of-range framework config now fails startup** ([#747](https://github.com/cyanheads/mcp-ts-core/issues/747), [#767](https://github.com/cyanheads/mcp-ts-core/issues/767), [#769](https://github.com/cyanheads/mcp-ts-core/issues/769)): count variables (`MCP_HTTP_PORT`, `MCP_HTTP_MAX_BODY_BYTES`, `MCP_HTTP_MAX_PORT_RETRIES`, `MCP_HEARTBEAT_MISS_THRESHOLD`, and the `CANVAS_*` counts) must be integers; every timer variable (`MCP_HTTP_PORT_RETRY_DELAY_MS`, `MCP_STATEFUL_SESSION_STALE_TIMEOUT_MS`, `MCP_HEARTBEAT_INTERVAL_MS`, `MCP_GC_PRESSURE_INTERVAL_MS`, `OAUTH_JWKS_COOLDOWN_MS`, `OAUTH_JWKS_TIMEOUT_MS`, `CANVAS_SWEEPER_INTERVAL_MS`, `SPEECH_TTS_TIMEOUT`, `SPEECH_STT_TIMEOUT`) must be an integer within `setTimeout`'s range (`0`–`2147483647`, minimum `1` where zero would expire at once); `LLM_DEFAULT_MAX_TOKENS` must be at least `1` and `LLM_DEFAULT_TOP_K` at least `0`.
- **Config failures name the variable** ([#746](https://github.com/cyanheads/mcp-ts-core/issues/746), [#628](https://github.com/cyanheads/mcp-ts-core/issues/628)): the startup banner and the `ConfigurationError`'s `data.issues` (`{ envVar, path, message, code }`) read `CANVAS_DEFAULT_ROW_LIMIT (canvas.defaultRowLimit): …` rather than `Invalid application configuration.`. `parseEnvConfig` attributes a failure inside a field, such as an array element or a property of a JSON variable, to the variable that fed it (`MY_ENDPOINTS (endpoints.0.url)`).
- **Tool error and trailer text in `content[]` gains Markdown escapes** ([#760](https://github.com/cyanheads/mcp-ts-core/issues/760), [#640](https://github.com/cyanheads/mcp-ts-core/issues/640)): the `Error:` message, `Recovery:` hint, and `reason` of an error result, and the string values of the `echo`, `delta`, and generic enrichment trailer lines, render through `escapeMarkdownInline`. `structuredContent` is unchanged.
- **`MarkdownBuilder.link()`, `.image()`, and `.badge()` render through `markdownLink` and `markdownImage`** ([#758](https://github.com/cyanheads/mcp-ts-core/issues/758)): the label is escaped and the destination wrapped in `<…>` (`[text](<url>)`), a URL that is not absolute `http(s)` renders as literal text, and `badge()` doubles `-` and `_` in its label and message.
- **CORS exposes `WWW-Authenticate` and `Retry-After`** with `Mcp-Session-Id` ([#687](https://github.com/cyanheads/mcp-ts-core/issues/687)), so a browser client can read a 401's `resource_metadata` challenge.
- **HTTP shutdown answers `503` while draining** ([#749](https://github.com/cyanheads/mcp-ts-core/issues/749)): from the start of `stop`, the MCP endpoint answers every request with a `-32000` error and `Retry-After: 1`, and each response closes its socket. A request on an open connection used to get a `500` `-32603` "This MCP handler has been closed".
- **`PdfParser` load failures are `ValidationError`** ([#763](https://github.com/cyanheads/mcp-ts-core/issues/763), [#680](https://github.com/cyanheads/mcp-ts-core/issues/680)): `extractText` on bytes pdf.js cannot read (no PDF structure, a bad trailer `/Root`, encryption) and `mergePdfs` / `splitPdf` on a source pdf-lib cannot load were `InternalError`; `loadDocument`, `mergePdfs`, and `splitPdf` also reject a document with no catalog.
- **`devcheck` Security Audit** ([#764](https://github.com/cyanheads/mcp-ts-core/issues/764)) fails a block that a direct dependency shares with a transitive copy only when the copy installed at the root is in a high or critical advisory's range; otherwise it warns, naming the dev tool.
- **The shared Biome config (`@cyanheads/mcp-ts-core/biome`) names no Biome version in its `$schema`** ([#771](https://github.com/cyanheads/mcp-ts-core/issues/771)): it points at the schema bundled with the installed `@biomejs/biome`, so a consumer on a newer Biome minor no longer sees a schema-mismatch diagnostic. Markdown files are outside its `files.includes` (`!**/*.md`).

## Fixed

- **Importing the package no longer parses framework config** ([#746](https://github.com/cyanheads/mcp-ts-core/issues/746)): an invalid variable surfaces at `createApp()` instead of crashing every subpath at import.
- **A handler that returns after its request was cancelled settles as `RequestCancelled` (`-32011`)** ([#753](https://github.com/cyanheads/mcp-ts-core/issues/753)), for tools, resources, and `runToolContract`. A fan-out that folded the aborted leg into a partial result used to be recorded as a success.
- **A cancelled `prompts/get` settles as `RequestCancelled`** ([#770](https://github.com/cyanheads/mcp-ts-core/issues/770)), and its completion record carries `-32011`.
- **HTTP shutdown with a request in flight no longer waits the full 5 s drain** ([#757](https://github.com/cyanheads/mcp-ts-core/issues/757)): in-flight exchanges on both the stateless and stateful arms are aborted, and idle keep-alive sockets close as their responses end.
- **`splitPdf` validates every range before copying a page** ([#680](https://github.com/cyanheads/mcp-ts-core/issues/680)): a non-integer, reversed, or out-of-bounds range is a `ValidationError`.

## Security

- **`createWorkerHandler()` without `name`, `version`, or `sessionMode` applies its Worker bindings** ([#746](https://github.com/cyanheads/mcp-ts-core/issues/746)): config parsed before the bindings were injected was kept, so bindings such as `MCP_AUTH_MODE` and `ENVIRONMENT` did not take effect. The handler now drops cached config on its first request. Worker deployments should upgrade.
- **The canvas SQL gate refuses a bare `current_schema`** ([#756](https://github.com/cyanheads/mcp-ts-core/issues/756)), which DuckDB binds as the function. This includes a staged column of that name; qualify it with its table (`c.current_schema`).
- **Log redaction matches a secret name run into another word** ([#702](https://github.com/cyanheads/mcp-ts-core/issues/702)): `DBPASSWORD`, `accesstoken`, `AWSSECRETACCESSKEY`, `api_keys`, `secrets`, and credential-token lists such as `accessTokens` are redacted; `max_tokens` and `PASSWORDLESS` are not.
