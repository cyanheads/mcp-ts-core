# 0.13.8 — 2026-09-26

## Added

- **OTLP log export** ([#547](https://github.com/cyanheads/mcp-ts-core/issues/547)) — `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` attaches a `BatchLogRecordProcessor`, and the framework logger forwards each record that passes the level filter and rate limit, redacted, with its MCP level as the severity. The base `OTEL_EXPORTER_OTLP_ENDPOINT` never enables it; `interactions.log` is never exported.
- **Failed-call payload logging** ([#291](https://github.com/cyanheads/mcp-ts-core/issues/291)) — `LOG_TOOL_FAILURE_PAYLOADS=true` writes one `Tool failure payload: <tool>` record per failed call with `toolInput` and `toolResult` as redacted JSON strings, capped by `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES` (default `16384`). Cancellations and `input_required` write nothing; redaction is by key name only. Backed by the new `sanitization.serializeForLogging(value, maxBytes)`.
- **`mcp.tool.rejections` counter and `mcp.tool.outcome` attribute** ([#546](https://github.com/cyanheads/mcp-ts-core/issues/546)) — a call refused by argument validation or the inline `auth` check counts once on `mcp.tool.rejections` (`mcp.tool.error_code`, `mcp.tool.error_category`); `mcp.tool.calls` and `mcp.tool.errors` carry `ok` / `error` / `cancelled`.
- **`mcp.error.category` on `mcp.errors.classified`** ([#481](https://github.com/cyanheads/mcp-ts-core/issues/481)) — the same `upstream` / `server` / `client` bucket as the per-surface counters, so the canvas tenant-cap refusal reads `-32003` + `server`.
- **`lint:packaging` check 13** ([#469](https://github.com/cyanheads/mcp-ts-core/issues/469)) — with `manifest.json` present, a `files` allowlist covering `dist/` must carry `"!dist/*.mcpb"`. The scaffold's `package.json` now does.
- **Skill-version overshoot check** — in the framework repo, `devcheck` warns when a skill's `metadata.version` is more than one step past its version at the last release tag.

## Changed

- **Output-contract failures are `InternalError`, and error counters follow the wire code** ([#480](https://github.com/cyanheads/mcp-ts-core/issues/480)) — a tool `output`, `enrichment`, or resource `output` violation returns `-32603` naming the definition and contract, with no `data`, in production and `runToolContract` alike. A non-`McpError` from a tool or prompt handler is bucketed by the code it classifies to, so `Error('Request timed out')` is `upstream` on every counter.
- **Engine resource-limit `RangeError`s are `InternalError`** ([#482](https://github.com/cyanheads/mcp-ts-core/issues/482)) — a whole message of `Maximum call stack size exceeded` (with or without the period), `Invalid string length`, or `Out of memory` maps to `-32603`; other `RangeError`s stay `ValidationError`.
- **`selectSections` rejects unknown names** ([#477](https://github.com/cyanheads/mcp-ts-core/issues/477)) — throws `InvalidParams` naming the unmatched and available keys, with both in `data` (`unmatched`, `available`). An absent `alwaysKeep` key is still ignored.
- **`InMemoryProvider.set` and `list` reject** ([#544](https://github.com/cyanheads/mcp-ts-core/issues/544)) — the encode, capacity, and cursor failures return a rejected promise instead of throwing synchronously.
- **`prefer-mcp-error-in-handler` reads Bun's handler source** ([#465](https://github.com/cyanheads/mcp-ts-core/issues/465)) — `throw Error(…)` counts as a plain-`Error` throw, so the rule now fires under Bun and on a bare `throw Error(…)`. `preserve-cause-on-rethrow` accepts `{ cause }` when the catch binding is `cause`.
- **Stable `data.reason` on framework validation errors** ([#552](https://github.com/cyanheads/mcp-ts-core/issues/552), [#504](https://github.com/cyanheads/mcp-ts-core/issues/504)) — with a `recovery.hint` where the caller can change the input: `sanitization` (`invalid_url`, `invalid_path`, `path_traversal`, `absolute_path_disallowed`, `invalid_json`, `json_too_large`, `invalid_number`, `unsupported_sanitize_context`), `fetchWithTimeout` (`invalid_url`, `private_address_blocked`, `too_many_redirects`), `IdGenerator` (`invalid_charset`, `unknown_entity_type`, `invalid_id_format`), `decodeCursor` / `paginateArray` (`invalid_cursor`), and the parsers (`parser_input_empty`, `csv_parse_failed`).
- **The startup line separates disabled tools** ([#514](https://github.com/cyanheads/mcp-ts-core/issues/514)) — `N tool(s) (+M disabled: …)`, with a `disabledTools` array beside `tools`; `manifest.definitionCounts` still counts every definition.
- **Docker production stage** ([#549](https://github.com/cyanheads/mcp-ts-core/issues/549)) — the OTEL step installs each package at its `peerDependencies` range (see Security), and the framework image installs them instead of skipping its own peers. `MCP_FORCE_CONSOLE_LOGGING`, which nothing read, is gone from both Dockerfiles.
- **`git-wrapup` orders `chore(deps)` first** ([#485](https://github.com/cyanheads/mcp-ts-core/issues/485)) — a dependency bump lands before the commits that use it and builds on its own, and every work commit must pass its tests at its own SHA, checked from a `git archive` snapshot. `maintenance` notes that a Bun pin moves `packageManager`, the Docker base tags, and the README badge together.
- Skill versions: `api-auth` 1.3 → 1.4, `api-canvas` 2.4 → 2.5, `api-config` 1.20 → 1.21, `api-context` 2.6 → 2.7, `api-errors` 1.16 → 1.17, `api-linter` 1.18 → 1.19, `api-telemetry` 1.13 → 1.14, `api-testing` 1.11 → 1.12, `api-utils` 2.12 → 2.13, `git-wrapup` 1.25 → 1.26, `maintenance` 2.9 → 2.10, `polish-docs-meta` 2.18 → 2.19, `release-and-publish` 2.20 → 2.21, `techniques` 0.3 → 0.4.

## Fixed

- **A caller-side deadline is `Timeout`** ([#551](https://github.com/cyanheads/mcp-ts-core/issues/551)) — `fetchWithTimeout` reports an external-signal abort whose reason is a `TimeoutError` as `-32004` with `data.errorSource: 'FetchSignalTimeout'`; any other abort stays `RequestCancelled`.
- **Canvas `missing_table` means a missing table** ([#484](https://github.com/cyanheads/mcp-ts-core/issues/484)) — an unknown function, table function, type, collation, or schema is `invalid_sql` with `data.binderMessage`; `tableName` carries the full name, spaces included, and a `FROM`-first query counts as a `SELECT`. A `DROP`, `DELETE`, `INSERT`, `UPDATE`, or `ALTER` naming a missing table is `non_select_statement` (`-32007`), not `missing_table`, in `query()` and `registerView()` alike.
- **`describe-on-fields` survives a self-referential schema** ([#491](https://github.com/cyanheads/mcp-ts-core/issues/491)) — the walk stops when a schema re-enters its own path, so the rest of the lint report survives.
- **`OUTLINE_VARIANT`'s documented shape lints clean** ([#271](https://github.com/cyanheads/mcp-ts-core/issues/271)) — `enrichment-prefer-block` skips a `notice` beside a `sections` array, and the JSDoc and `techniques` snippet describe `kind` and the section item.
- **`MarkdownBuilder.inlineCode` sizes its code span** ([#505](https://github.com/cyanheads/mcp-ts-core/issues/505)) — the delimiter outgrows any backtick run in the value, so it reads back as one span; `formatOutline` renders section names the same way.
- **`ctx.log` keeps its line on the wire** ([#502](https://github.com/cyanheads/mcp-ts-core/issues/502)) — `message` and `error` are written after the call's data, so a `message` key no longer replaces the log line in `notifications/message`.
- **Canonical context fields win in log records** ([#550](https://github.com/cyanheads/mcp-ts-core/issues/550)) — an `extra` key named `requestId`, `traceId`, `spanId`, `sessionId`, `tenantId`, `operation`, or `timestamp` no longer replaces the context's own value.
- **An unwritable logs directory no longer kills the process** ([#497](https://github.com/cyanheads/mcp-ts-core/issues/497)) — each file sink is probed at startup; one that cannot be opened is dropped with a single `warning` naming it, and stderr keeps logging.
- **`MCP_LOG_LEVEL=debug` reaches stderr** ([#511](https://github.com/cyanheads/mcp-ts-core/issues/511)) — the stderr, stdout, pretty, and `combined.log` targets take `level: 'debug'`, so the logger's level is the only gate, after `setLevel()` too; `error.log` keeps `error`.
- **One OTel diag logger, on stderr** ([#545](https://github.com/cyanheads/mcp-ts-core/issues/545)) — `NodeSDK` no longer registers a second one from `OTEL_LOG_LEVEL`, so the overwrite notices and the `Unknown log level` warning on aliases are gone and stdio's stdout carries only JSON-RPC. The metrics reader's export timeout matches its 15 s interval, ending the clamp notice.
- **`createFetchMock` static routes settle on Node** ([#503](https://github.com/cyanheads/mcp-ts-core/issues/503)) — the body is read once and served as a fresh `Response` per call instead of a `clone()` tee, so a cancelled body resolves.
- **`runToolContract` settles cancellation like production** ([#513](https://github.com/cyanheads/mcp-ts-core/issues/513)) — once `context.signal` has fired, anything the handler or success pipeline throws becomes `RequestCancelled`; argument parsing stays outside the settle.
- **The pre-commit hook no longer rewrites files** ([#543](https://github.com/cyanheads/mcp-ts-core/issues/543)) — `.husky/pre-commit` passes `--no-fix` instead of the removed `--no-format`, so Biome checks without writing.

## Security

- **Request context no longer reaches client error data** ([#548](https://github.com/cyanheads/mcp-ts-core/issues/548)) — `ErrorHandler.handleError` and every framework `McpError` site (storage validation and providers, parsers, formatters, `fetchWithTimeout`, speech and LLM providers, auth, sessions, canvas) pass explicit fields only, so `ctx.inputs.responses` and request metadata stay in the log. Formatter failures no longer put a stack in `data`, and the no-auth-context `-32006` carries no scope names.
- **The Docker OTEL install passes the supply-chain guards** ([#475](https://github.com/cyanheads/mcp-ts-core/issues/475)) — both Dockerfiles copy `bunfig.toml` into the production stage and seed the Socket scanner from the build stage, so the OTEL packages resolve through the release-age gate and the scanner, inside the framework's tested peer ranges.
