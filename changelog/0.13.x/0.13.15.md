# 0.13.15 — 2026-10-12

## Changed

- **The canvas SQL gate refuses more** ([#729](https://github.com/cyanheads/mcp-ts-core/issues/729)): `current_setting`, `current_schema`, `current_schemas`, `in_search_path`, `query_table`, `read_duckdb`, `parquet_full_metadata`, and `parquet_bloom_probe`, and `query()` with anything but a single string literal (a literal's SQL is gated as its own statement, up to four levels deep). A table reference that names a file (a name holding a dot, or a qualifier the canvas's database lacks) is rejected as `sql_read_only`.
- **`CANVAS_MAX_CANVASES_PER_TENANT` defaults to 500** (was 100); every caller shares one tenant under `MCP_AUTH_MODE=none`.
- **`@modelcontextprotocol/server` `^2.3.1`; `@opentelemetry/*` 0.x peer ranges `^0.223.0`** (`instrumentation-pino` `^0.69.0`).
- **`prompts/get` without `arguments` is validated as `{}`** (`@modelcontextprotocol/server` 2.3): a prompt whose arguments are all optional now answers instead of refusing the call, and a missing required argument's `-32602` names the field (`message: Invalid input: expected string, received undefined`, was `Invalid input: expected object, received undefined`). `tools/list` and tool-argument validation are unchanged.
- **Tool-argument handling moved to `tools/utils/arguments/`**, out of `toolHandlerFactory.ts` and `inputPrevalidation.ts` (internal; `InputHandlingOptions` still exports from the package root).
- **Skills** — `api-canvas` 2.8, `api-config` 1.26, `api-errors` 1.23, `api-telemetry` 1.21, `api-utils` 2.18, `field-test` 2.22, `polish-docs-meta` 2.23, `security-pass` 1.13, `git-wrapup` 1.30.

## Fixed

- **A canvas call aborted before the engine starts executing now rejects as cancelled** ([#662](https://github.com/cyanheads/mcp-ts-core/issues/662)); a `query()` that registers a table and then rejects drops it.
- **`Tool failure payload: <tool>` records are exempt from the log rate limiter** ([#735](https://github.com/cyanheads/mcp-ts-core/issues/735)): every failed call keeps its payload under `LOG_TOOL_FAILURE_PAYLOADS`; its `Error in tool:` record keeps the limit.
- **A `ZodError` reaches logs, spans, and the client mirror as its one-line summary** ([#736](https://github.com/cyanheads/mcp-ts-core/issues/736)): record `message`, `stack` header, and cause-chain nodes no longer carry Zod's JSON of every issue.
- **`createFetchMock` keeps each `Request` until `reset()`** ([#625](https://github.com/cyanheads/mcp-ts-core/issues/625)), so a garbage collection no longer drops a later abort from `request.signal`.

## Security

- **Each canvas's DuckDB instance runs with `enable_external_access` off, `allowed_directories` limited to the export root and its scratch directory, and `lock_configuration` on** ([#729](https://github.com/cyanheads/mcp-ts-core/issues/729)), under a new parse-tree layer in the SQL gate. `CANVAS_EXPORT_PATH` is now the engine's file surface.
- **A `ZodError`'s `data.issues` is bounded on every path `classifyOnly` serves** ([#710](https://github.com/cyanheads/mcp-ts-core/issues/710)): a resource `params` rejection, a `ZodError` a tool or resource handler throws, `ctx.state.get(key, schema)`, and `runToolContract` carry the argument rejection's caps (10 issues, `issuesCount` beside a cut list), so one request no longer returns an unbounded issue list.
