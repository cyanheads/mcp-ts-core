# 0.13.17 — 2026-10-25

## Added

- **`bun run test:soak`** ([#787](https://github.com/cyanheads/mcp-ts-core/issues/787)): rebuilds, sends 25,000 stateless HTTP `tools/call` requests (both protocol eras, 16 concurrent) to a built-package fixture on Bun, and fails when the post-GC heap grows more than 64 MiB. It runs beside `test:package` in the release gate, outside `test:all`.
- **`@duckdb/node-api` peer range gains `^2.0.0-r.1`** ([#778](https://github.com/cyanheads/mcp-ts-core/issues/778)), keeping `^1.5.5-r.1 || ^1.5.6-r.1`.

## Changed

- **`headerParam()` rejects a `number`-typed property** (MCP SDK 2.4): `tool()` throws at definition, `lint:mcp` reports it as `header-param-designation`, and the message points to `z.int()` or `z.string()`. `string`, `integer`, and `boolean` are the permitted types.
- **Telemetry adopts OpenTelemetry JS 3** ([#766](https://github.com/cyanheads/mcp-ts-core/issues/766)): the trace peer is `@opentelemetry/sdk-trace` (was `sdk-trace-node`), `BatchSpanProcessor` takes `{ exporter }`, and log export reads the Logs API from `@opentelemetry/api`. Log export needs two optional peers, `@opentelemetry/sdk-logs` and `@opentelemetry/exporter-logs-otlp-http`; `@opentelemetry/api-logs` is no longer a peer.
- **The canvas SQL gate and engine setup cover DuckDB 2** ([#778](https://github.com/cyanheads/mcp-ts-core/issues/778)): `query()` literals are admitted in the 1.5 and 2.0 parse shapes; `read_single_csv_file`, `read_single_json_file`, `read_single_parquet_file`, `index_key`, and the `*_external_resource*` functions are refused; a `SHOW` subject is checked as a file reference; `lambda_syntax = 'ENABLE_SINGLE_ARROW'` keeps `x -> x + 1` working; each engine runs at most one thread per 64 MB of `memory_limit`, so exports under a tight limit spill rather than run out of memory.
- **Re-registering a canvas table is atomic** ([#659](https://github.com/cyanheads/mcp-ts-core/issues/659)): `registerTable` and `importFrom` replace the table in one transaction, so a failing source, a value that fails conversion, or an abort leaves the previous table and its TTL (or no table, on a first registration).
- **`minimumReleaseAge` is 1 day** in the repo `bunfig.toml` and `templates/_bunfig.toml` (was 3 days), so a release's dependency floors install in a scaffolded server the day they ship.
- **The bug report forms and `report-issue-*` skills use one Environment table** in place of separate version, runtime, transport, and OS fields.
- **Skills** — `add-tool` 2.36, `api-canvas` 2.10, `api-config` 1.28, `api-context` 2.14, `api-linter` 1.23, `api-telemetry` 1.23, `field-test` 2.24, `polish-docs-meta` 2.25, `report-issue-framework` 1.15, `report-issue-local` 1.13, `security-pass` 1.15.

## Fixed

- **`spillover()` closes its source on every early exit** ([#661](https://github.com/cyanheads/mcp-ts-core/issues/661)): the `maxRows` cap, an abort, or a failed registration runs the iterator's `return()`, so a generator's `finally` executes.
- **Every line of an enrichment `notice` is quoted** ([#765](https://github.com/cyanheads/mcp-ts-core/issues/765)): a line break used to end the trailer blockquote, and the rest of the notice rendered as top-level Markdown in `content[]`.
- **`withRetry`, the pacer, the HTTP error handler, the startup banner, and the input-required sealer read thrown values through the guarded helpers** ([#701](https://github.com/cyanheads/mcp-ts-core/issues/701)): a value whose `data`, `code`, or `result` throws on read no longer rejects with the getter's own error, strands a pacer slot, or replaces the startup error.

## Security

- **HTTP requests no longer leak through the shutdown signal** ([#786](https://github.com/cyanheads/mcp-ts-core/issues/786)): 0.13.16 retained ~71 KiB per request, so sustained traffic from any client grew the heap until the process ran out of memory. Each exchange now has its own `AbortController`, released when its response ends; `close()` still aborts those in flight.
