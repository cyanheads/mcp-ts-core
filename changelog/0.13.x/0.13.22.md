# 0.13.22 — 2026-11-08

## Changed

- **`engines.bun` rises to `>=1.4.4`** in the framework and the scaffold ([#632](https://github.com/cyanheads/mcp-ts-core/issues/632)). Opening a SQLite mirror store on an older Bun throws `ConfigurationError` (`data.reason: 'unsupported_bun_version'`) naming the floor and the running version, before any file or directory is created. `SqliteHandle.exec` documents that the first failing statement throws and nothing after it runs; `createApp()` still checks only Node.js.
- **`httpErrorFromResponse` and `fetchWithTimeout` keep a captured upstream error body off client envelopes** ([#590](https://github.com/cyanheads/mcp-ts-core/issues/590)). `error.data.body` and `error.data.responseBody` hold the captured body on the thrown error, `withRetry`'s exhausted error, and an `McpError` rebuilt from `{ ...error.data }`, and failure records log them; a tool's `structuredContent.error.data`, a resource or prompt JSON-RPC `error.data`, the URL-elicitation handback, `ErrorHandler.formatError`, and the HTTP transport's error response leave both keys out. `exposeBody: true` / `exposeErrorBody: true` send both keys to the client per call; a `body` passed in `data` reaches the client as given.
- **The HTTP transport's error response reads thrown `data` as every other client envelope does**: a field the wire cannot carry is sent as `'[Unreadable]'` instead of failing the response.
- **A tool or resource handler's return type is its `output` schema's input side (`z.input`)**, and `ctx.enrich` takes the enrichment fields' input types; `format()` and `enrichmentTrailer.render` still receive parsed values. A `.default()` field may be omitted from the return ([#846](https://github.com/cyanheads/mcp-ts-core/issues/846)).
- **Skills** — `add-resource` 1.10, `add-service` 1.13, `add-tool` 2.39, `api-canvas` 2.15, `api-config` 1.32, `api-context` 2.19, `api-errors` 1.28, `api-linter` 1.25, `api-mirror` 1.10, `api-utils` 2.23, `api-workers` 1.13, `polish-docs-meta` 2.27, `security-pass` 1.16.
- `AuthContext.token` JSDoc: never relay the bearer token to an upstream API.
- **`htmlExtractor.extract` documents that extraction runs synchronously on the calling thread, takes no abort signal, and that `maxBytes` bounds input size, not CPU time**; a server extracting untrusted HTML runs it off its serving thread. The `api-utils` parsing reference gains an `htmlExtractor` entry (docs only, [#755](https://github.com/cyanheads/mcp-ts-core/issues/755)).

## Fixed

- **`filesystem` storage stores every valid key exactly as written** ([#656](https://github.com/cyanheads/mcp-ts-core/issues/656)): `a` and `a/b` coexist; `x/./y`, `m//n`, `t/`, `.`, `/`, and `/lead` round-trip and list as written; keys that differ only in case stay distinct. Data lives under `<STORAGE_FILESYSTEM_PATH>/_v2/` with every name percent-encoded, and an existing store is copied there once on first start. An uppercase letter or `.` takes three bytes of a name, so a key's last segment holds at most 250 lowercase, 125 alternating-dot, or 83 uppercase characters (was 255) and a directory segment 255 lowercase or 85 uppercase; a longer one throws `ValidationError` before any filesystem call, and a batch holding one changes nothing.
- **`cloudflare-kv` and `cloudflare-r2` reject a key whose stored name (`<tenantId>:<key>`) passes the backend's limit** (512 bytes on KV, 1,024 on R2) with `ValidationError` (`-32007`) before any binding call, where the backend's rejection surfaced as `InternalError` ([#840](https://github.com/cyanheads/mcp-ts-core/issues/840)). The message names the longest key the tenant can use, `data.key` is cut to 50 characters and never carries the tenant, and a `getMany`/`setMany`/`deleteMany` holding one rejects before any entry is touched.
- **KV `list` accepts any `limit` up to 10,000** (it asks KV for at most 1,000 and returns the native cursor; was `Invalid key_count_limit`), and R2 `deleteMany` sends at most 1,000 keys per call.
- **A caller abort or caller-side deadline that cuts a non-2xx body capture throws `RequestCancelled` (`FetchAborted`) or `Timeout` (`FetchSignalTimeout`)** instead of the status-mapped error with `body: 'Could not read response body'`, so `withRetry` no longer retries a 5xx the caller abandoned ([#604](https://github.com/cyanheads/mcp-ts-core/issues/604)). A `timeoutMs` that cuts only the capture keeps the status mapping.
- **A `fetch` rejection named `AbortError` while neither the `timeoutMs` signal nor the caller's `signal` aborted is `ServiceUnavailable`** (`FetchNetworkErrorWrapper`, `originalErrorName: 'AbortError'`, the rejection as `cause`) and `withRetry` retries it, instead of `RequestCancelled` ([#799](https://github.com/cyanheads/mcp-ts-core/issues/799)).
- **A 2xx body that fails mid-stream with neither signal behind it rejects with `ServiceUnavailable`** (`FetchNetworkErrorWrapper`, the runtime error as `cause`) instead of the raw runtime error; an `AbortError` from the body stream is classified the same way ([#819](https://github.com/cyanheads/mcp-ts-core/issues/819)).
- **The ElevenLabs, Whisper, and `ISpeechProvider` `@throws` docs name what they throw**; `add-service` maps 504 to `Timeout` and other 5xx to `ServiceUnavailable`.
- **A tool output field whose parsed value is not valid input to the field itself (`z.stringbool()`, a cross-type `.pipe()`, `z.codec()`) returns its parsed value** instead of failing every successful call ([#846](https://github.com/cyanheads/mcp-ts-core/issues/846)). Enrichment values are parsed against the `enrichment` block alone and merged onto the parsed domain value, so an output transform runs once on both surfaces; `tools/list` is unchanged.
- **A successful tool result carrying a top-level `error` key fails as `-32603`** naming the output (or enrichment) contract: an open `output` root (`.passthrough()`/`.catchall()`) that returns one undeclared, or keeps one enriched from the service layer. Under an open root, an enriched key naming a declared `output` field fails the same way, naming the enrichment contract, rather than replacing that field's parsed value.
- **Argument repair reports a value whose representation is fixed but still fails `.min()`, `.max()`, `.length()`, or `.multipleOf()` with that check** ([#745](https://github.com/cyanheads/mcp-ts-core/issues/745)): `{ limit: '600' }` against `z.number().max(500)` reports `limit: Too big: expected number to be <=500`, not `Send limit as a number, not a string.`
- **A stringified list under a wrapping `z.preprocess()` is reported as sent** when the repair is refused for what it decodes to (`tags.0: Invalid input: expected number, received string`).
- **An argument rejection's message and hint no longer render the `too_big` / `too_small` Zod raises when `.min()`, `.max()`, or `.length()` runs on a value of the wrong type** ([#719](https://github.com/cyanheads/mcp-ts-core/issues/719)); a string sent for `z.array(…).max(10)` reads `barcodes: Invalid input: expected array, received string`. `data.issues` keeps both issues.
- **A union branch that refuses a value as a type no longer hides the branch that failed inside it** when Zod also measured the value's length: `["5"]` against `z.union([z.string().min(2), z.array(z.number())])` validates as `[5]`.
- **Representation repair no longer writes a value read at a non-index key of a `z.preprocess()`-produced list (`"1.0"`, `"01"`, `"-0"`, `""`) into the element that key reads as a number**, and leaves the argument as sent when that list owns a key besides its elements, as under `coerce: false`.
- **`pdfParser.extractText` destroys the pdf.js document it opens** after the text pass, whether extraction resolves or rejects ([#810](https://github.com/cyanheads/mcp-ts-core/issues/810)). A failed destroy fails a call whose extraction succeeded (`InternalError`, `pdf_text_extract_failed`) and never replaces an extraction failure.
- **Canvas path-export symlink coverage** ([#334](https://github.com/cyanheads/mcp-ts-core/issues/334)): tests pin that a symlink at the export path fails the check with `export_path_symlink` and leaves the link and its target untouched, and that the rename replaces the link rather than writing through it. `api-canvas` and `security-pass` state that `CANVAS_EXPORT_PATH` must be writable only by the server's own user.

## Security

- **`filesystem` storage gives every valid tenant ID its own directory on every filesystem** ([#845](https://github.com/cyanheads/mcp-ts-core/issues/845)), so no tenant reads, lists, overwrites, deletes, or clears another's `ctx.state`: the directory is the encoded ID when it fits the 255-byte name limit, otherwise `%%` and the ID's SHA-256 in lowercase hex. The one-time copy of the earlier layout copies each tenant directory to the tenant it is named for only.
- **Captured upstream error bodies stay on the server**: the helpers' `body` and `responseBody` never reach a client envelope unless a call sets `exposeBody` / `exposeErrorBody`.
- **Argument repair costs a small multiple of the failed first parse** to repair, re-parse, and accept or reject, however many values the arguments hold ([#739](https://github.com/cyanheads/mcp-ts-core/issues/739)). Which calls validate, the values handlers receive, and every rejection are unchanged.
