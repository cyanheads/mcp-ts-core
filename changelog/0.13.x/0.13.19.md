# 0.13.19 — 2026-11-05

## Added

- **`DataCanvas.acquireShared(ctx, { stateKey?, create?, onReplace? })`** ([#598](https://github.com/cyanheads/mcp-ts-core/issues/598)): resolves the canvas whose id `ctx.state` holds and mints it once under concurrent first calls, one resolution at a time per tenant and `stateKey`. `onReplace(previousId)` runs under that lock when no live canvas is found, and `previousId` is `undefined` for a canvas that reached its absolute cap. `AcquireSharedOptions` is exported from `@cyanheads/mcp-ts-core/canvas`.
- **Mirror sync lease** ([#517](https://github.com/cyanheads/mcp-ts-core/issues/517)): with the SQLite store, `runSync` claims a cross-process lease, so an init CLI, a scheduled refresh, and every session on one store file never sync at once. A held lease rejects `Conflict` with `data.reason: 'sync_locked'`, and a run whose lapsed lease another run took over rejects `'sync_lease_lost'`; `defineMirror({ syncLeaseTtlMs })` sets the expiry (default 2 minutes). `SyncLease` and `SyncLeaseStore` are exported.
- **`literals` on `ErrorFactoryOptions`** ([#818](https://github.com/cyanheads/mcp-ts-core/issues/818)): values a message or recovery hint quotes for the caller to send back verbatim. A tool error's `content[]` renders each occurrence as a code span, so the copied value carries no backslash; `structuredContent.error` and the log record are unchanged. `ctx.fail` and every factory take it, and `decodeCursor` declares `cursor` and `nextCursor`.

## Changed

- **The tool-error trailer gains a `retry after <value>` term** ([#627](https://github.com/cyanheads/mcp-ts-core/issues/627)) between `retryable` and the request id, rendered from `data.retryAfter`: `(reason rate_limited · retryable · retry after 30)`. A test pinning the whole trailer line sees it.
- **With the SQLite store, `runSync` commits each page and the state through the sync lease**, not through the store's `applyBatch`/`writeState`: a wrapper that overrides those must omit `syncLease` (`const { syncLease, ...rest } = store`). A holder that dies keeps the lease until `syncLeaseTtlMs` lapses. The lease only fences processes running 0.13.19 or later.
- **An installed server resolves its app root to its own package** ([#641](https://github.com/cyanheads/mcp-ts-core/issues/641)) when launched from the installing project's root or a workspace package. `serverInfo`, a relative `skills` folder, and the default or a relative `LOGS_DIR` follow the server, so logs move from `<project>/logs` to `<project>/node_modules/<server>/logs`; set an absolute `LOGS_DIR` to keep them in the project.
- **Canvas SQL gate refusals:** a statement naming a file is `sql_read_only` with `"<path>" names a file, not a staged table.` (a named reader is `denied_function`), whether or not the file exists, so a table named by a missing path is now that refusal, not `missing_table`. A single statement that parses but is not a SELECT is `non_select_statement` with `Canvas query must be SELECT.` and `statementType: 'UNKNOWN'` (previously `Canvas query must be SELECT; got <TYPE>.` with the prepared type, or a could-not-be-prepared message; text that does not parse keeps its message), and one naming a path outside the canvas's directories (a `COPY … TO` a file) moves from `sql_read_only` to `non_select_statement`. Under `denySystemCatalogs`, a column, alias, or CTE spelled exactly like a DuckDB internal metadata view is refused too.
- **`canvas_capacity_exhausted` names no drop tool** ([#748](https://github.com/cyanheads/mcp-ts-core/issues/748)): the hint says to reuse a held `canvas_id` or retry once idle canvases expire, because a table drop or `clear()` frees no slot; only `DataCanvas.drop` does.
- **Canvas recovery hints follow the engine's error class** ([#803](https://github.com/cyanheads/mcp-ts-core/issues/803)): a SELECT-shaped statement that fails to parse takes a syntax hint naming the bare-alias case, with `data.reason` still `invalid_sql` and `binderMessage` populated, and `sql_parse_error` names that case too. One that fails to prepare takes a hint for its class: a `Catalog Error` points at the function, type, collation, or schema name reported missing, an `Invalid Input Error` at the rejected constant argument, an `IO Error` back to the staged tables, and a binder error keeps the column-or-function hint. `sql_execution_error` splits the same way: `Conversion Error` keeps the `TRY_CAST` hint, and `Invalid Input Error` and `Out of Range Error` take their own.
- **The eager `init*Metrics()` startup calls are removed:** counters and histograms are created on first use, and a path a server never takes (a rate-limit rejection, a heartbeat failure) exports no series.
- **`devcheck --only` also runs optional checks** it matches, and `release:github` accepts `--help`/`-h`.
- **`codeSpan('')` and `MarkdownBuilder.inlineCode('')` render nothing** ([#795](https://github.com/cyanheads/mcp-ts-core/issues/795)), which a CommonMark parse reads back as the empty value; two backticks read as literal text.
- **Skills** — `add-skill` 1.1, `add-tool` 2.38, `api-canvas` 2.12, `api-config` 1.29, `api-context` 2.16, `api-errors` 1.25, `api-linter` 1.24, `api-mirror` 1.7, `api-telemetry` 1.24, `api-utils` 2.21, `code-simplifier` 1.8, `design-mcp-server` 2.35, `field-test` 2.26, `git-wrapup` 1.33, `orchestrations` 1.15, `release-and-publish` 2.26, `release-pr-review` 1.9.

## Fixed

- **`clean-mcpb` and `lint-packaging` strip agent docs only at an installed package's root** ([#794](https://github.com/cyanheads/mcp-ts-core/issues/794), [#820](https://github.com/cyanheads/mcp-ts-core/issues/820)): `framework-skills/`, `skills/`, `.claude/`, `.agents/`, `AGENTS.md`, and `CLAUDE.md` at a package root, and `SKILL.md` anywhere. The SDK's `dist/ext/skills/` modules stay, so cleaned MCPBs start; a dependency's root `AGENTS.md` no longer ships. `CRITICAL_RUNTIME_PATHS` accepts both `@opentelemetry/semantic-conventions` layouts.
- **`lint-packaging.ts` and `lint-mcp.ts` no longer name repo-only `../src` paths** ([#797](https://github.com/cyanheads/mcp-ts-core/issues/797)), which failed the typecheck of any consumer whose tests import a copied script. `test:package` now typechecks every shipped script in the installed scaffold.
- **`release-github.ts` parses arguments strictly** ([#817](https://github.com/cyanheads/mcp-ts-core/issues/817)): an unknown option, a positional, or a value on a flag exits 1 before anything runs, instead of falling through to a real release. A `gh` that cannot be started fails the run instead of reporting success ([#823](https://github.com/cyanheads/mcp-ts-core/issues/823)).
- **`devcheck` rejects unknown flags and an `--only` that is empty or matches no check** ([#691](https://github.com/cyanheads/mcp-ts-core/issues/691)); both exit 1 before any check runs.
- **Metric helpers called before the SDK starts export** ([#806](https://github.com/cyanheads/mcp-ts-core/issues/806)): `createCounter`, `createUpDownCounter`, and `createHistogram` resolve their instrument from the global `MeterProvider` on each record, so module scope and `setup()` are safe places to create them. `getMeter()` and `createObservableGauge()` still bind when called.
- **A second `initializeOpenTelemetry()` after `shutdownOpenTelemetry()` exports** ([#821](https://github.com/cyanheads/mcp-ts-core/issues/821)): shutdown releases the `@opentelemetry/api` globals the SDK registered. Leave `OTEL_ENABLED` off in a process that registers its own SDK, since its registrations are released too.
- **A migration runs exactly once per database** ([#815](https://github.com/cyanheads/mcp-ts-core/issues/815)): `runMigrations` reads the stored version and applies each migration with its version stamp in one `BEGIN IMMEDIATE` transaction. Concurrent openers wait and then skip it, a stamp that fails to land rolls the migration back, and an opener with an older spec no longer lowers the stored version.
- **`SHOW <table>` answers on DuckDB 2** ([#800](https://github.com/cyanheads/mcp-ts-core/issues/800)): the plan allowlist admits the operator DuckDB 2 plans it as, and every `pragma_*` function is refused by name.
- **A parser error from the `registerAs` CTAS is a typed `sql_parse_error`** ([#752](https://github.com/cyanheads/mcp-ts-core/issues/752)), not an untyped `DatabaseError`; `classifyDuckdbError` reads both the bare and the `Failed to extract statements:` forms.

## Security

- **`escapeMarkdownInline` runs in time linear in its input** ([#809](https://github.com/cyanheads/mcp-ts-core/issues/809)).
- **Canvas SQL gate hardening:** a statement naming a file fails the same way whatever the file's state and wherever it is; a single statement that parses but is not a SELECT is refused before the engine prepares it, with one refusal whatever it names; every `pragma_*` function is refused however it is quoted, cased, or qualified; the plan check reads the function each scan names; under `denySystemCatalogs` DuckDB's internal metadata views are refused by name.
