# 0.13.20 — 2026-11-06

## Added

- **`createApp()` refuses a Node.js below `engines.node`** ([#642](https://github.com/cyanheads/mcp-ts-core/issues/642)): on real Node.js below 24.0.0 it prints the startup banner and exits 1 before `setup()`, naming the running version and binary; the error carries `data.reason: 'unsupported_node_version'`. Bun, Deno, and Worker isolates are not checked.
- **JWT mode warns at startup without an audience** ([#731](https://github.com/cyanheads/mcp-ts-core/issues/731)): one `warning` when `MCP_AUTH_SECRET_KEY` is set and `MCP_JWT_EXPECTED_AUDIENCE` is not. Validation is unchanged; `.env.example` and `templates/.env.example` list `MCP_JWT_EXPECTED_AUDIENCE` and `MCP_JWT_EXPECTED_ISSUER`.

## Changed

- **The canvas SQL gate admits `range()` and `generate_series()` as table functions** ([#822](https://github.com/cyanheads/mcp-ts-core/issues/822)) with constant arguments; a lateral or subquery argument is still refused. A `Binder Error` DuckDB raises when an admitted statement runs is now `ValidationError` with `data.reason: 'sql_execution_error'`, previously `DatabaseError`.
- **Skills** — `api-auth` 1.8, `api-canvas` 2.13, `api-config` 1.30, `api-context` 2.17, `api-errors` 1.26, `api-mirror` 1.8, `api-telemetry` 1.25.

## Fixed

- **A resource handler's SDK `ProtocolError` keeps its code and `data`** ([#583](https://github.com/cyanheads/mcp-ts-core/issues/583)): they reach the client, and `ResourceNotFoundError` answers `-32602` with `data` exactly `{ uri }`, as the SDK's own not-found does. Tools and prompts are unchanged.
- **A failed resource read writes one `Error in resource:<name>` record and one `mcp.errors.classified` count** ([#734](https://github.com/cyanheads/mcp-ts-core/issues/734)), at the level the definition's error contract sets through `severity`.
- **Mirror `runSync` resumes only a run of its own mode** ([#664](https://github.com/cyanheads/mcp-ts-core/issues/664), [#751](https://github.com/cyanheads/mcp-ts-core/issues/751)): an `init` no longer takes a failed `refresh`'s cursor and checkpoint, and an interrupted `refresh` resumes from its cursor instead of its checkpoint. The SQLite store adds a `mode` column to `mirror_sync_state` on open.
- **Mirror values bind alike on Bun and Node** ([#665](https://github.com/cyanheads/mcp-ts-core/issues/665)): a boolean binds as `1`/`0`; an out-of-range `bigint`, or an object, array, or `Date` in a record, tombstone, id, filter, or `match`, rejects with `ValidationError` naming where it sat.
- **`getByIds` matches `INTEGER`, `REAL`, and `NUMERIC` primary keys** ([#663](https://github.com/cyanheads/mcp-ts-core/issues/663)) as SQLite's `pk = ?` does, in the requested order, and no longer fails at 32,767 or more ids on Node.
- **D1 `getMany` accepts 99 or more keys** ([#654](https://github.com/cyanheads/mcp-ts-core/issues/654)): keys are de-duplicated and read in chunks of 98 through one `db.batch()`, so `ctx.state.list` works on a large D1 page.
- **Protected-resource metadata's fallback `resource` follows `MCP_HTTP_ENDPOINT_PATH`** ([#684](https://github.com/cyanheads/mcp-ts-core/issues/684)), where it was always the public origin plus `/mcp`.
- **The `401` challenge is well-formed for any server name or `MCP_PUBLIC_URL`** ([#686](https://github.com/cyanheads/mcp-ts-core/issues/686)): the realm is a quoted-string, and the public URL is serialized through `new URL()` before the protected-resource metadata, the challenge's `resource_metadata`, and the server card carry it.
- **CSV and JSON canvas `export()` no longer runs out of memory on wide rows** ([#793](https://github.com/cyanheads/mcp-ts-core/issues/793)): row order and a view's `ORDER BY` hold, and memory no longer grows with the table's row count; tested at 20,000 rows of 4,096 characters (CSV) and 40,000 rows of 2,048 characters (JSON) on a 128 MB canvas. The export writes on one engine thread, so a large one takes roughly two to three times as long on a many-core host. Parquet export and `importFrom` are unchanged.

## Security

- **A session bound to an identity resumes only for a request whose tenant ID, client ID, and subject each equal the session's** ([#730](https://github.com/cyanheads/mcp-ts-core/issues/730)): an absent field equals only an absent or empty-string one. A mismatch is answered `404`, as an unknown session is, on POST, GET, and DELETE.
